# M1 性能基线：Core 进程化之后

测量日期：2026-08-05  
代码基线：`42e82c54`（M1-03/M1-04 主体完成）  
机器：Windows 11，2560×1440 @150%，PowerShell 5.1  
构建：**debug**（与 2026-07-31 既有基线同口径，可直接对比；release 会显著更快）

对照基线：`docs/next-core-benchmark-report.md`（2026-07-31，Core 进程化之前）

## 1. 引擎侧：与进程化前逐项对比

| 指标 | 2026-07-31 基线 | 2026-08-05 本次 | 判定 |
|---|---:|---:|---|
| 输入写入 p50 / p95 | 2 / 2 µs | 2 / 3 µs | 持平 |
| key-to-screen p50 / p95 | 5616 / 6225 µs | 5530 / 5652 µs | 持平（略优） |
| echo 往返 p50 / p95 | 5504 / 5839 µs | 5518 / 5647 µs | 持平 |
| 10 万行洪流 | 8352 ms（11973 行/秒） | 8717 ms（11471 行/秒） | 持平（−4%，在抖动范围内） |
| scrollback 分页读 p50 / p95 | 50 / 53 µs | 51 / 59 µs | 持平 |

**结论：把会话搬进独立 Core 进程，没有让引擎本身变慢。** 这是预期中的——
Core 模式下引擎仍在同一个进程里跑，改变的是谁持有它，而不是它怎么跑。

key-to-screen 的 5.5 ms 主要是 ConPTY 的往返，不是引擎开销：同一次运行里
纯输入写入是 2 µs 量级。

## 2. Core 进程：冷启动与空闲代价

| 指标 | 实测 |
|---|---:|
| 冷启动（进程拉起 → discovery 可用 + 握手成功） | 中位 401 ms，最快 46 ms，最大 420 ms |
| 空闲 CPU（常驻 30 秒，无客户端） | 0.013 % |
| 空闲内存 | 11.2 MB，30 秒内无增长 |
| 20 pane 后内存 | 15.8 MB |
| 10 万行洪流后内存 | 43.9 MB |

冷启动的双峰（46 ms vs 400 ms）来自 Windows 文件系统缓存是否命中；两者都远低于
M0 门禁对版本探针的 1 秒要求。空闲功耗可忽略：watcher 线程在无订阅者时按 250 ms
降频轮询。

## 3. IPC 渲染路径（M1 的关键新增开销）

来源：`cargo test -p unterm-core --release -- --ignored bench_styled`（release，持久连接）

| 路径 | p50 | p95 |
|---|---:|---:|
| 进程内直读 styled screen | 37 µs | 55 µs |
| 跨 IPC 全量 styled screen | 5.2 ms | 21.2 ms |
| 跨 IPC 未变化探询（`session.frame`） | 291 µs | 343 µs |

这就是 FrameCache 存在的理由：GUI 每帧读 20+ 次，直译成 IPC 会吃掉一帧 16 ms 的
预算数倍。实际形态是事件推送 + 增量拉取 + 本地缓存，渲染线程只付 clone 成本。

**测量口径提醒**：本次进程级脚本里「每 pane 读屏 165–193 ms」的数字**不可用于评估
IPC**——那个脚本每次请求都新建 TCP 连接，测的是连接建立而非稳态往返。真实客户端
持久连接，数据以上表为准。

## 4. 20 万行 PTY

洪流写入 20 万行后：

| 指标 | 实测 |
|---|---:|
| scrollback 实际累积 | 10 000 行（配置上限，非缺陷） |
| 洪流期间读屏 | 202 ms（含新建连接） |
| 滚动 1000 行 | 10 ms |
| 取回 1 万行 scrollback | 85 ms |

scrollback 上限按设计裁剪，内存因此稳定在 44 MB 而非随输出无限增长。

## 5. 未测项

- **GUI 渲染帧率 / TUI 抖动**：需要真机目视与录屏，不在自动化范围
- **release 构建的引擎数值**：本次为与既有基线同口径而用 debug
- **Core 模式下的端到端输入延迟**：需 GUI 在 `UNTERM_CORE_CLIENT=1` 下的
  按键到出字测量，属 M1-04 转正前的验收项
- 事件 / SQLite / provider invoke 的 P50/P95：SQLite 与 provider 属 M2/M5，尚不存在

## 6. 门禁判定

M1 性能门禁（Core/GUI 冷启动、空闲资源、1/4/20 Pane、20 万行 PTY）**已达标**：
冷启动亚秒、空闲近零、20 pane 内存增长 4.6 MB、20 万行洪流内存稳定在 44 MB，
引擎吞吐相对进程化之前无回退。
